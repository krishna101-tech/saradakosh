## Snapshot and rollback sequence

1. Read the live Sheet with values, formula values, rich text hyperlink runs, row/cell formatting, sheet properties and named ranges. Record source revision/modified time if available. Compare to the expected baseline; stop on concurrent drift.
2. Create a native full spreadsheet backup and a local restricted snapshot before changing any source cell. Export a machine-readable JSON including rich-text links and an XLSX backup, then hash each file and read the native copy back. Private Drive/NotebookLM columns stay private and outside Git. Also keep the current curated public snapshot and manifests as immutable historical inputs.
3. Back up the SQLite database consistently with SQLite backup API; include schema, table counts, foreign-key state and deterministic row hashes of every non-library domain table. Record existing library book summaries, link rows, covers and provenance. Never use a filesystem copy of a live WAL database as the sole backup.
4. Implement explicit version2 source parsing with stable IDs, visibility and canonical relations. The existing importer explicitly requires168 sequential row-derived IDs, fixed range/hash and identical identity count; change it through a versioned migration, never weaken checks globally. Version1 snapshots must still parse deterministically as historical input.
5. Within one SQLite transaction, preserve `library_books` rows and summaries. Add visibility/canonical relation data (a relation table or constrained columns), retaining originals. Do not cascade delete or renumber. Link provenance must keep legacy source book ID, original language/label/URL and original order. Attach independently approved useful links to32 with unique labels and section/volume annotations; deduplicate identical URLs without losing originating IDs. Retire ID38's independent-cover visibility without deleting historical rights provenance.
6. Restrict public repository reads/search/filter/pagination/counts to visible canonical rows. A hidden row must not leak as a separate result, but its title alias and approved deep anchors remain discoverable under32. Do not change events, parameters, relationships, schedule data or other domain tables.
7. Validate in a disposable DB first: all168 stable historical IDs; expected approved visible count; map targets exist; no alias cycles; existing summaries and all domain hashes unchanged; links/languages/volume order correct; `foreign_key_check` clean. Exercise rollback with an intentional failure mid-migration and prove byte/logical state restoration.
8. Apply accepted Sheet metadata changes with precise bounded ranges and preimage comparison; read back values and rich-text links. Snapshot that new revision, regenerate source/manifest/approved link ledger, then import the exact frozen snapshot. There is no atomic cross-service Sheet+SQLite transaction: if import fails, restore the precise Sheet preimage and verify readback before continuing.
9. Run source/importer/library tests, full build/lint and browser mobile/list/card/keyboard/search/pagination checks on the final revision. Independent QA must approve edition/link/cover evidence and final stats. Preview only the accepted milestone with exact commit/revision integrity; no merge/production before owner acceptance.

Rollback restores the native Sheet backup/preimage and verified rich-text hyperlinks, restores the consistent SQLite backup, and reverts the version2 public snapshot/migration/UI commit together. Keep historical manifests and relation decisions; no destructive renumbering makes reversal depend on inferred row arithmetic.

Raw inventories and temporary PDF/image inspection files are external in the restricted local evidence directory. Repository artifacts retain bounded facts, URLs and hashes; no reader bodies or cover binaries are rehosted here.
