# System Architecture

This document provides a high-level overview of the application architecture and details the SQLite database schema that drives the project.

## 🏗️ System Overview

The application utilizes a decentralized, multi-stack approach communicating with a single source of truth:

1. **The Client (Next.js):** Reads database records via the `better-sqlite3` driver. This layer is strictly for rendering the UI and handling user-facing interactions.
2. **The Admin Dashboard (Flask):** Serves as a RESTful CMS via `sqlite3`, enabling pagination and content inspection.
3. **Data Processors (Python CLI Scripts):** Standalone scripts like `generate_report.py` and `import_to_sqlite.py` perform heavy ETL (Extract, Transform, Load) tasks, bypassing the web layers to manipulate the database directly.

## 🗄️ Database Schema Documentation

The primary database is a local file named `saradakosh.db`. Below is the structural layout of its core tables.

### `events`
Stores the core chronological or sequential events and their metadata.
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY | Unique identifier for the event. |
| `du` | TEXT | | Descriptive context or identifier string. |
| `ref` | TEXT | | Reference code or citation string. |
| `type` / `type_2` | TEXT | | Classification categories for the event. |
| `dt` / `mn` / `yr` | REAL | | Date information (Date, Month, Year). |
| `sequence` | REAL | | Ordering sequence for sorting records. |
| `field1` / `field2` | TEXT | | Additional metadata fields. |
| `child_id` | REAL | | Relational reference to child elements. |
| `gujarati` / `new_guj` | TEXT | | Localized text content. |

### `parameters`
Holds categorization entities and specific descriptive tags.
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY | Unique identifier for the parameter. |
| `para1` | TEXT | | Name or label of the parameter. |
| `type` | TEXT | | Category classification. |
| `sequence` | REAL | | Ordering sequence. |
| `person` | TEXT | | Associated person entity. |
| `remark` - `remark4` | TEXT | | Supplementary description fields. |

### `event_parameters` (Join Table)
Maps the many-to-many relationship between `events` and `parameters`.
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `event_id` | INTEGER | FK -> `events(id)` | Foreign key to the event. |
| `parameter_id` | INTEGER | FK -> `parameters(id)` | Foreign key to the parameter. |

### `param_hierarchy`
Defines recursive, hierarchical relationships between parameters (e.g., Parent/Child nested tags).
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `uid` | INTEGER | PRIMARY KEY | Unique identifier for the hierarchy mapping. |
| `parent_id` | INTEGER | FK -> `parameters(id)` | Foreign key to the parent parameter. |
| `child_id` | INTEGER | FK -> `parameters(id)` | Foreign key to the primary child parameter. |
| `child2_id` | INTEGER | FK -> `parameters(id)` | Foreign key to a secondary child parameter. |

### `schedule_settings` & `schedule_topics`
| Table | Core Columns | Description |
| :--- | :--- | :--- |
| `schedule_settings` | `id` (PK), `start_date`, `google_meet_link` | Global configuration for meeting scheduling. |
| `schedule_topics` | `id` (PK), `order_idx`, `name`, `playlist_link` | Stores distinct scheduled topics and multimedia links. |

## ⚡ Indexes & Performance

**Current State:**
The database relies on implicit indexes generated by `PRIMARY KEY` constraints. There are currently **no explicit custom indexes** on foreign keys or highly queried columns.

**Optimization Recommendations:**
For large datasets, lookups on join tables and hierarchy tables will experience table scans. We recommend implementing the following indexes in future schema updates:
```sql
CREATE INDEX idx_event_params_event ON event_parameters(event_id);
CREATE INDEX idx_event_params_param ON event_parameters(parameter_id);
CREATE INDEX idx_param_hier_parent ON param_hierarchy(parent_id);
```
