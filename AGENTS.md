2. Read this repository's `PROJECT_ENGINEERING.md` and live GitHub Issue/PR/review state before substantial work.
3. GitHub is the only software project-management source of truth. Do not create a parallel Trello/Linear/Jira task system.
4. The product owner's only operational command is `go`.
5. For an implementation agent, `go` means discover/resume the canonical actionable GitHub task, synchronize repository state, implement coherently, test, push evidence, and return `REVIEW_READY` without asking the owner for task IDs or branches.
6. System architecture outranks prompt-local convenience. Search for existing ownership before adding new services/helpers/state, prefer root-cause fixes, avoid duplicate sources of truth, and do not self-accept substantial work.
7. General engineering lessons discovered in this project must be proposed upward for the portfolio standard; project-specific lessons belong in `PROJECT_ENGINEERING.md`.
