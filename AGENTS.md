# SaradaKosh agent routing

1. SaradaKosh is governed by the Portfolio Platform. Read the central standard at `https://github.com/krishna101-tech/software-engineering-standards/blob/main/STANDARD.md` and the single canonical model-role allocation at `https://github.com/krishna101-tech/software-engineering-standards/blob/main/docs/AAA_RUNTIME_PROFILE.md`.
2. Project intent is governed by the canonical Drive Logbook `SaradaKosh_Logbook.md` in the `Software Architecture` folder. No Portfolio Platform Version is assigned yet; do not invent one or create new product scope from repository history alone.
3. Read `PROJECT_ENGINEERING.md` plus the live GitHub Issue, PR, current head, review threads, and validation evidence before substantial work. GitHub is authoritative for execution state.
4. The owner's normal operational command is `go`. Select only a canonical actionable Task; do not ask the owner to carry issue numbers, branches, SHAs, or handoff files.
5. Do not define permanent Luna/Antigravity/Sol roles locally. The central runtime profile is the only portfolio-wide role authority.
6. If GitHub, Vercel, a model provider, or another metered provider reports an explicit quota/plan/cost block, record it once and do not retry the forbidden action until an authoritative state change or reset condition occurs.
7. For user-facing web behavior, real-browser validation is required before final acceptance when the Task materially affects the deployed experience.
8. General portfolio lessons belong in the central Portfolio Platform. This file should remain a small router, not a duplicate operating manual.
